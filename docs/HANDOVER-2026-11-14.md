## 一、产品定义（先对齐前提，别搞错）

Folio 是一个阅读器，**双端同源但各自独立**：

- **桌面端**（Windows，Electron + React + Vite）：正身。有书架、书市（网络书源）、
  局域网 HTTP 服务。
- **安卓端**：**独立的阅读器，不是桌面端的遥控器**。同步只是它的一个功能。
  - 本机导入的 txt 书，双端整文件双向同步，断网可读
  - 云端书（小说/漫画）**只能连上桌面端在线读，一个字节都不许落盘**

两类书的技术事实（会反复用到）：

| | 本地书 | 云端书 |
| --- | --- | --- |
| `kind` | `local` | `cloud` |
| 正文 | 桌面 `books/<base>.txt`（UTF-8），手机 `books/<id>.txt` | 在书源那边，只经桌面端代理转发 |
| `type` | `0`（只有 txt） | `0` 小说 / `2` 漫画 |
| 可整文件同步 | 是（≤30MiB） | **永远否** |

支持的格式：**只有 txt**，不支持 epub/mobi/cbz。编码自动识别 UTF-16 BOM → UTF-8 BOM →
严格 UTF-8 → GBK。

| 方法 | 路径 | 要点 |
| --- | --- | --- |

| error | 桌面端显示 |
| --- | --- |

### 在线态判定（设计文档已修正，别改回去）

```
online = deviceSseCount(id) > 0
       || (now - offlineAt(id) > 90_000 && now - lastSeenAt <= 90_000)
```

`offlineAt` 是 SSE 显式断开时记的**纯内存**标记，**优先级高于 90 秒弱在线窗口**。
原因：手机只在前台开 SSE，最后一根断开就等于 App 不在前台了；这时还报在线，
用户会对着锁屏的手机发指令、等一个永远不会执行的队列。`upsertSeen()` 会清掉
`offlineAt`（下一次心跳说明 App 还活着）。`online` 和 SSE 计数**绝不落盘**。

## 六、硬约束（破一条就是返工）

1. **云端书零缓存**。云端小说正文、漫画图片**一个字节都不许写磁盘**。
   只允许内存缓存（章节 LRU 3 章、图片 LruCache 按 `byteCount` 计量）。
   新增任何 `FileOutputStream` / `writeBytes` 前，先确认它不会碰到云端书。
2. **传输串行**。局域网单连接已接近带宽上限，并发只会让状态翻倍、续传难写。
3. **`contentHash` 是 `sha1(规整后的 UTF-8 正文)`**，不是原始文件字节。
   用原始字节会让 GBK 的书每次同步都判成"内容不同"，无限重传。
4. **指令只携带"做什么"，不带字节**。三类指令的传输 100% 复用
   `/api/book/:id/download` 和 `/api/upload/*`，不要新写传输逻辑。
5. **幂等**。`push-book` 已有同 hash → done；`remove-book` 没有这本书 → done；
   `pull-book` 桌面已有同 hash → done。回执 `done` 不等于"我传了"，等于"目标状态已达成"。
6. **旧桌面端兼容**。设备接口遇到 404/501/`features` 没有 `devices`，
   一律静默降级成"不支持"，**绝不能让 `ConnectionManager` 判定连接失败**。
   否则没升级桌面端的老用户会突然连不上。
7. **二进制 body 绝不能用 `readBody()`**——它内部 `Buffer.toString('utf8')`，
   会把分块上传的字节毁掉。用 `readBodyBuffer(req, limit)`。
8. **文案禁词**：`正在同步` / `已同步到手机` / `同步中`。手机不在线时不能暗示
   "正在发生什么"。`_device-copy-check.mjs` 会盯着这个。

## 七、踩过的坑（别再踩一遍）

1. **Gradle 缓存假绿**。不加 `--rerun-tasks --no-build-cache`，编译失败也可能报
   BUILD SUCCESSFUL。**所有"我跑过了"的结论都必须带这两个参数。**
2. **`android/local.properties` 原本不存在**，`./gradlew` 直接报
   "SDK location not found"。已修好，别删。
3. **测试夹具的 `hashOf()` 只对 seed < 256 生成 40 位 hash**。
   原来写 `seed.toString(16).padStart(2,'0').repeat(20)`，seed ≥ 256 时十六进制变 3 位，
   拼出来 60 位，被 `filter { contentHash.length == 40 }` 全滤掉——于是"最新的那本"
   永远进不了快照，看着像生产代码没排序。已改成 `padStart(8,'0').repeat(5)`。
   **写测试造 hash 时一定断言长度是 40。**
4. **`_qa-lan-edge.mjs` 曾经开箱即红**。裸夹具下 16 条 FAIL，因为它依赖
   `--big` / `--comic` / `--dirty` 三种夹具开关。现在改成先探测夹具能力、缺什么
   打 `[SKIP]` 并说明怎么补，完整跑法 `npm run check:lan-edge`。
   **不要靠删断言让它变绿。**
5. **`Bookshelf.jsx` 原本没有任何右键菜单**（全项目 `contextmenu` 为 0）。
   现在是本次新补的最小实现，别以为有现成机制。
6. **`writeBookCopy()` 不能给上传复用**：它的名字后缀是 `sha1('sha1-<hash>')[:8]`，
   而且会把 Buffer 转 String 再重写 UTF-8。上传落盘走的是 `commitUpload()` 直接
   `.part` → rename。
7. **`LazyColumn` 的 key 必须带分区前缀**。书可能同时出现在「继续阅读」和「本机书」
   两个分区，只用 `book-<id>` 当 key 会抛 `Key was already used` 把书架打死（3.0.0 真机崩过）。
   现在是 `"book-${section.key}-${book.id}"`。
8. **UDP 45678 端口**可能被真实的 Folio 桌面端占着，发现类测试会 `assumeTrue` 跳过。
   看到「跳过 1 项」不是失败。
9. **测试脚本跑起来别只看 `BUILD SUCCESSFUL`**，去 `app/build/test-results/testDebugUnitTest/*.xml`
   数 `tests`/`failures`。Gradle 的退出码不带测试失败计数。
10. **桌面端 `devices:list` 的 `pending` 含 `delivered`**（已领取未回执），
    不是单纯 `state === 'pending'`。改这块前先看 `devicestore.js` 的 `pendingCount`。
