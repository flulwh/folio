# Android 3.0 增量 PRD：从"桌面端遥控器"改为独立阅读器

> 版本：3.0（增量）｜状态：待评审｜基线：桌面端 2.5.0 + Android 2.5.0
> 技术栈：沿用 Kotlin + Jetpack Compose，不换框架；重做的是数据层、书源模型和阅读器形态
> 本文只写"相对 2.5.0 要改什么"，不重复描述已上线能力

---

## 1. 产品定位重述

**Folio 安卓版是一个能自己导入 txt 的独立阅读器，跨端同步只是它的一个功能。**

三条推论（后面所有需求都由这三条推出）：

- **没有桌面端也是完整形态**：导入、建书架、读小说、读漫画以外的本地书，全都不依赖网络。
- **连接桌面端是增强，不是前提**：入口退到设置里，未连接不阻塞任何本地操作。
- **云端书是"连接时才可用的资源"，不是书架资产**：元数据可以落本地用于展示，正文/图片一律不落盘。

## 2. 两类书源的模型

### 2.1 三类书的定义

| 类别 | 标记 | 正文在哪 | 能否离线 | 能否被同步成整文件 |
| --- | --- | --- | --- | --- |
| **A 本机书** | `origin=local` | 手机私有目录 `books/<id>.txt` | 能 | 能（传给桌面端） |
| **B 桌面端本地书** | `origin=desktop, kind=local` | 桌面端 `books/*.txt`（手机还没有） | 不能 | 能（从桌面端拉下来，到位后即变 A） |
| **C 桌面端云端书** | `origin=desktop, kind=cloud`，`type 0=小说 / 2=漫画` | 桌面端书源实时抓 | 不能，**零缓存** | 不能（永远同步不了） |

关键规则：

1. **本机是否有全文，由 `hasLocalFile` 决定，不由来源决定**。B 同步完成后就是一本 A，只保留 `origin` 用于展示"来自桌面端"。
2. **书架真相 = 手机本地持久化**（books / progress / pending-sync / sync-state 四组逻辑数据），不再以 `/api/state` 为准。`/api/state` 只用于连接后的对齐。
3. **B/C 的元数据（id、书名、作者、封面、type）在连接时落本地**，目的只有一个：未连接时能显示出来并给出正确提示，而不是凭空消失。
4. 云端书的**进度**和**元数据**可以落盘，**正文和图片不能**。

### 2.2 可见性状态表

| 书类 | 未连接 | 已连接 | 阅读中连接中断 |
| --- | --- | --- | --- |
| A 本机书 | 可读；进度写本地并挂 pending | 可读；进度回写；参与整文件同步 | 继续读，不打断、不报错 |
| B 桌面端本地书（无全文） | 灰态，角标"待同步"；可点开，弹"连接桌面端后可下载全文"；不显示目录 | 自动整文件下载 → 转 A | 下载中断：丢弃临时文件、标记"未同步"，下次连接重试 |
| C 云端书（小说/漫画） | 灰态，角标"需连接"；点开弹提示 + [去连接]；不显示目录；进度只显示文字"上次读到 第 N 章" | 正常读（按章/按话拉取，仅内存） | 当前章已取到可读完；翻下一章失败显示"连接已断开 · 重试" |
| C 正在读、退出阅读器后断网 | 直接回灰态，正文已释放 | — | — |

补充：默认"桌面端书在未连接时可见但不可读"；设置里给一个开关"未连接时隐藏桌面端书"（P1），避免书架被灰条占满。书架筛选提供"只看本机书"。

## 3. 核心用户故事（Given / When / Then）

**US-1 纯离线首次使用**
Given 全新安装 + 飞行模式；When 用系统文件选择器选一个 GBK 编码的 txt；Then 3 秒内出现在书架，点开能读到第一段，全程无网络、无连接。

**US-2 重复导入**
Given 书架已有同内容文件；When 再导入同一个文件（或它的复制件，文件名可能不同）；Then 不新增条目，提示"这本书已经在书架里"，跳到该书并保留原进度。

**US-3 同名不同内容**
Given 已有《三体》A；When 导入另一个同名但内容不同的《三体》B；Then 视为两本独立书（标题加序号或按作者区分），不覆盖、不共用进度。

**US-4 手填连接**
Given 桌面端局域网面板已开并显示地址与访问码；When 填 `http://192.168.x.x:7788` + 访问码并点"测试连接"；Then 2 秒内显示"已连接"并展示桌面端书架；访问码错时提示"访问码不对"，网络不通时提示"连不上桌面端"，两种文案不能混。

**US-5 搜索连接**
Given 同一 Wi-Fi、桌面端 ≥2.5.0；When 点"搜索桌面端"；Then 5 秒内列出发现实例（名称 + IP + 端口），点选即填入地址，仍需手输访问码。

**US-6 双向补齐**
Given 已连接，两端各有一批本地书；When 执行同步；Then 按内容哈希做差集，缺书方收到整个文件；手机导入的书出现在桌面端书架，桌面端的本地书出现在手机书架，两端都能离线读。

**US-7 传输中断**
Given 一本 40MB 的 txt 传到一半 Wi-Fi 断了；When 重连后再同步；Then 从断点续传（或整本重传，方案二选一但必须定死），不产生重复条目、不产生半个文件、不覆盖已有进度。

**US-8 云端小说零缓存**
Given 已连接，读了某本云端小说的 3 章；When 退出阅读器并断网；Then App 私有目录与缓存目录没有新增任何章节正文文件；书架该书变灰"需连接"，点开提示不能离线读。

**US-9 云端漫画**
Given 已连接，打开 `type=2` 的漫画；When 上滑翻页、双指放大；Then 整页图逐张加载、可放大到 3x 看清气泡字、下一话首图提前预取、翻页不出现长白屏。

**US-10 离线进度补写**
Given 未连接状态下读了本机书 30 分钟；When 重新连接；Then 进度按 `updatedAt` 合并回写桌面端，桌面端显示同一位置；若桌面端更新，则保留桌面端的，不覆盖。

**US-11 冲突（两端同书不同内容）**
Given 两端都有《xxx》但内容哈希不同；When 同步；Then **不静默覆盖**，两端各留自己的文件，条目标"内容不一致"，用户可手动选"用手机版覆盖桌面端 / 用桌面版覆盖手机"，默认保持现状。

**US-12 删除一本书**
Given 书架里有一本本机书；When 长按删除并确认；Then 只删手机上的文件与本地进度，桌面端完全不受影响；对桌面端书删除等于"从手机书架移除"，不动桌面端数据。

## 4. 需求池

### P0（本期必须）

**P0-1 本机导入**
做什么：系统文件选择器（`ACTION_OPEN_DOCUMENT`，单本 + 多选，MIME 用 `text/plain` 加 `*/*` 兜底）；读取后做编码识别（BOM → UTF-16LE/BE；UTF-8 合法性校验；失败按 GBK 解码，判定顺序与桌面端一致），统一转 UTF-8 落 `books/<id>.txt`；从内容猜书名/作者；写元数据（`contentHash`、`size`、`encoding`、`addedAt`）。
去重：对**原始字节**算 `sha1` 作 `contentHash`；命中已有 hash 不新增条目，提示并跳转。
导入即读：导入完成立刻入库、立刻可打开，不等任何网络请求。
为什么：不做这个就没有 3.0，是独立阅读器的第一性问题。

**P0-2 书架与书源模型**
做什么：本地持久化承载 books（id、title、author、contentHash、size、encoding、origin、remoteId、type、hasLocalFile、cover、addedAt、lastReadAt、syncState）与 progress、pending、sync-state；App 启动只读本地，不发起网络请求。
为什么：把"遥控器"变成"阅读器"的根，其余需求全建在这上面。

**P0-3 连接桌面端**
做什么：手填地址 + 访问码，用 `GET /api/ping` 校验；三类错误分开报（访问码错 / 网络不通或防火墙 / 地址格式错）；UDP 45678 广播发现，只在点按后发一次，不常驻监听；连接信息与 token 持久化，token 变更自动标记"需重连"；回前台或用户操作时触发一次健康检查，不做常驻轮询。
为什么：连接是增强项，必须"能连、能诊断、连不上也不影响本地"。

**P0-4 云端书零缓存**
做什么：正文/图片只进内存——小说保留"当前章 + 上/下一章"共 3 章，漫画保留当前话 URL 清单 + 可见页 ±2 张解码结果；HTTP 响应对章节与图片强制 `no-store`，禁止写入任何缓存目录；离开阅读器即释放（含图片 bitmap）。
未连接呈现：书架灰态 + 角标"需连接"；点开是提示弹层（文案明确"云端书需要连接桌面端才能阅读"）+ [去连接]；不展示目录，不展示百分比，只显示"上次读到 第 N 章"。
为什么：用户明确要求，且这是与桌面端书源的责任边界。

**P0-5 本地书整文件双向同步**
做什么：
- 触发：连接成功后自动执行"清单对齐"（只换元数据 `[{hash,title,size}]`，不传文件）；需要传输的条目走手动确认（默认一次"同步 N 本，共 XX MB"，用户点开始）。设置可开"局域网下 ≤20MB 自动传"。
- 同书判定：`contentHash`（sha1 原始字节）为唯一主键；文件名只用于展示与冲突提示。
- 传输：小文件流式直传；大文件分块（4MB/块）+ 断点续传，服务端按 hash 落临时文件、校验通过后原子改名。
- 失败分类：网络中断（保留断点可续）、空间不足（上传前用 `StatFs` 预检，剩余 < 文件大小×1.2 直接拒绝并提示需腾出多少）、hash 校验失败（丢弃重传）、权限/访问码错误（停止整批并提示）。
- 中断清理：不保留半成品；条目回到"未同步"。
为什么：两条同步规则里唯一双向的一条，做错就是丢书或内容错乱。

**P0-6 冲突与同书策略**
做什么：同 hash = 同一本；同名不同 hash = 两本并存，标"内容不一致"，同步时不自动覆盖，给用户选；覆盖动作必须二次确认，且先备份被覆盖方（桌面端留 `books/<id>.bak.txt`，手机留 `.bak`）。
为什么：静默覆盖是数据丢失级别的体验问题，个人自用工具更该保守。

**P0-7 小说阅读器**
做什么：段落滚动（只组合可见段落）；切段规则必须与桌面端 `chapters.js` 一致，否则 `paraIndex` 会偏；字号 14–28sp、行距三档、字体两档、页边距、底色（纸白/米色/夜间）；目录（本机书本地正则切章、云端书取 `/api/toc`）+ 目录搜索 + 点章跳转；上下章切换；阅读页无动画、无常驻计时器。
为什么：主力场景，且"能读得下去"决定这个 App 是否被打开第二次。

**P0-8 漫画阅读器**
做什么：整页图片竖向滚动；未解码前用占位符固定高度，避免滚动跳动；双指缩放 1–3x、双击放大 2x、放大态可拖动平移；预加载当前话 ±2 张，读到本话末尾 80% 时预取下一话首 2 张；单张失败显示重试与原因，不整话失败；话内图片序号 `pageIndex` 只存本机。
图片来源：清单接口一并返回 `referer`，客户端带该头请求源站图片（部分源站校验防盗链）。
为什么：本期新增能力；漫画阅读体验主要输在"白屏"和"缩放糊"。

**P0-9 进度模型与合并**
做什么：本机书 `{paraIndex, chapterTitle, percent, updatedAt}`；云端小说 `{chapter, chapterIndex, windowBase, paraIndex, chapterTitle, percent, updatedAt}`；云端漫画用 `chapter/windowBase/paraIndex = 章序号`、`percent`（与桌面端 ComicReader 同构，章内页不参与同步）。
写路径：内存 → 600ms 防抖写本地 → 连接时 1.5s 节流 `POST /api/progress`；失败进 pending，下次连接/回前台补写。
对齐：连接时拉 `/api/state` 进度，按 `updatedAt` 新者赢 + 字段浅合并（沿用现有 `mergeProgressEntry`，不新造规则）；先合并再补写 pending。
为什么：进度是唯一被用户每天感知的跨端数据，口径一旦不一致，两端永远差几段。

**P0-10 删除**
做什么：本机书 → 删本地文件 + 本地进度（二次确认，文案写明"只删手机上的副本"）；桌面端书 → "从手机书架移除"，删本地元数据与进度缓存，桌面端不动。
为什么：语义不清的删除最容易误伤；本期不做"两端一起删"（桌面端无删除接口）。

**P0-11 桌面端配套接口（阻塞项，需与 3.0 同期发布 2.6.0）**
做什么：新增本地书清单、整文件上传（分块 + hash 校验 + 原子落盘 + 写入 books.json 与 books/ 副本）、整文件流式下载（突破 12MB）、云端漫画图片清单（`urls + referer`）。
为什么：现状 `MAX_BODY=512KB`、`MAX_TEXT=12MB`，且 `/api/chapter` 只返回文本、漫画无任何接口——不加接口，P0-5 与 P0-8 无法实现。

**P0-12 旧能力下线**（逐条见第 6 节）
为什么：留一半旧逻辑，零缓存和独立书架就永远有人绕过。

### P1（可选增强）

- 书架：筛选（全部/本机/桌面端/云端/在读）、排序、继续阅读卡、书名与作者搜索。
- 同步可视化：状态页列出每本书"已同步/待同步/内容不一致/失败原因"，单条重试，手动"立即同步"按钮。
- 传输进度条、后台传输与"仅 Wi-Fi 时传输"开关。
- 封面缓存（LRU 24）、桌面端书封面在未连接时可用。
- 漫画：横屏双页、日漫从右往左、亮度调节、阅读进度条按话内页定位。
- 阅读器：字号手势微调、进度条拖拽预览、段落长按复制。
- 未连接时隐藏桌面端书的开关。

### P2（以后再说）

- epub / mobi 导入（需要另写解析与版式引擎，且桌面端也不支持，两端会不一致）。
- 手机端书源管理与"书市"（等于把 `sources.js` + JS 引擎移植到手机，成本极高）。
- 多桌面端（家里 / 公司各一台）切换与优先级。
- TTS 朗读、自动滚动。
- "以较长内容为准"这类自动冲突策略。
- 云端书"收藏到本机"——**当前明确不做**（与零缓存规则冲突），若将来放开需重新评审。

## 5. 界面结构

**书架**
- 顶栏：标题 · 连接状态点（已连接 / 未连接 / 同步中）· 搜索
- 分区：继续阅读（最近在读 1–3 本）/ 本机书 / 桌面端书（未连接时整组灰态）
- 条目：封面、书名、作者、进度（百分比，或"未同步""需连接""内容不一致"角标）、来源小标（本机 / 桌面 / 云端·漫画）
- 空状态：主按钮"从文件导入 txt"，次按钮"连接桌面端"
- 未连接横幅："未连接桌面端 · [连接]"（可关闭，不重复弹）
- 长按：删除本机副本 / 从书架移除 / 查看同步状态

**阅读器 · 小说**
- 顶栏（可隐藏）：返回 · 书名 · 目录 · 更多
- 正文：可滚动段落列表，无分页
- 底部（可隐藏）：进度条 · 百分比 · 上一章 / 下一章
- 目录抽屉：章列表 + 搜索 + 当前章高亮
- 排版弹层：字号、行距、字体、底色、页边距

**阅读器 · 漫画**
- 顶栏（可隐藏）：返回 · 话标题 · 话选择
- 图片区：竖向滚动整页图；缩放 1–3x
- 底部：本话 X/Y 页 · 上一话 / 下一话
- 单张失败：占位 + 重试 + 错误原因

**设置**
- 桌面端连接：地址、访问码、测试连接、搜索桌面端、断开、当前状态与耗时
- 同步：自动同步开关、仅 Wi-Fi 传输、立即同步、上次同步时间、冲突列表入口
- 排版：小说默认字号/行距/字体/底色；漫画默认阅读方向
- 存储：本机书占用、缓存占用（应恒为 0，作为零缓存的自证）、清理入口
- 关于：App 版本、桌面端版本、网络诊断（端口/防火墙提示）

## 6. 明确要下线的旧能力

| # | 旧能力 | 现状 | 下线原因 |
| --- | --- | --- | --- |
| 1 | 云端书章节磁盘缓存 `offline/cloud/<hash>-<章>.txt` | 读过的章落盘 | 与"云端书只能连接时看"直接冲突 |
| 2 | "下载到手机"（前 12 章 `OFFLINE_CHAPTER_LIMIT`） | 预取 12 章 | 同上 |
| 3 | `ChapterFallback` 断网退到最近缓存章 | 断网续读 | 零缓存后无章节可退，留着只会掩盖错误 |
| 4 | "书架 = `/api/state`"这一前提 | 未连接即空书架 | 独立阅读器必须以本地持久化为真相 |
| 5 | 本地书"未缓存则现拉 `/api/book/:id`" | 隐式拉全文 | 改为显式整文件同步，语义与失败处理都更清楚 |
| 6 | WorkManager 15 分钟周期拉书架/拉章 | 后台周期拉取 | 不再需要后台拉正文；只保留"待补写进度"的重试（连接时 / 回前台 / 下次打开） |

## 7. 待确认问题（最多 5 条，都会改变实现方案）

1. **本期能否同步改桌面端（2.6.0）？** 双向同步与漫画都依赖桌面端新增接口；若只能改 Android，这两块必须整体降到 P1。
2. **漫画图片走桌面端代理还是手机直连源站？** 部分源站校验 Referer/防盗链，直连可能 403；代理稳但桌面端要多转发一层流量，也影响"零缓存"的带宽口径。
3. **同步触发要不要"连接即自动传文件"？** 当前定的是"自动对清单、传文件需确认"；若要完全无感，需接受连接瞬间可能占用几十 MB 带宽。
4. **单本 txt 上限定多少？** 建议 30MB，超过只在本机读、不参与同步；否则必须做分块断点续传（工期 +3~5 天）。
5. **删除是否需要"两端一起删"？** 桌面端目前没有删除接口，做的话要新增 DELETE 与两阶段确认；不做则删除永远只影响本机。
