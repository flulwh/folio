## 一、启动与数据安全（最高优先级）

| 状态 | 问题 | 处理 |
| --- | --- | --- |
| ✅ | `decodeText()` 不认 UTF-16，Windows 记事本「Unicode」保存的 txt 被当二进制拒绝（`isProbablyBinary` 见到 `0x00` 就判定二进制） | 加 `0xFF 0xFE → utf-16le`、`0xFE 0xFF → utf-16be`（失败时 `swap16` 重解），`isProbablyBinary` 见到 UTF-16 BOM 直接放行；`src/utils/format.js` 的 `decodeBuffer()`（拖拽导入路径）同步修 |
| ✅ | 删空书架后重启，`restoreFromBackup()` 会用 `.bak` 把已删的书恢复回来 | 新增 `markExplicitlyCleared()` 写 `<file>.cleared` 指纹；清空 books/progress/rules/sources 时打指纹；`restoreFromBackup()` 见到指纹就跳过并清掉 `.bak`；恢复成功一次也删 `.bak` |
| ✅ | `writeJson` 遇到 EPERM 直接抛出，被 `uncaughtException` 抓成「启动出错」弹窗（用户实际遇到过） | 可写性探测 + 兜底数据目录（`FOLIO_DATA_DIR` → `%TEMP%\Folio-data` → 程序目录）；写盘失败只提示一次；`.bak` 备份 + 启动自愈 |
| ✅ | 双开互相覆盖 books/progress | 单实例保护。**注意**：`app.requestSingleInstanceLock()` 会把锁文件写进 userData，在 `%APPDATA%` 受限的机器上直接拿不到锁（`Lock file can not be created! Error code: 5`），程序会在开窗前退出——已改为数据目录下的 `instance.json`（pid 存活检测 + 退出时清理） |
| ✅ | `book:read` / `book:load-path` / `book:delete-file` 接受任意路径 | `isKnownBookPath()` 校验（`books/` 前缀或 books.json 登记过），`delete-file` 另有 `books/` 前缀硬校验 |
| ✅ | `source:import-file`、`rules:import-file` 用 `readFileSync(path,'utf-8')`，GBK/BOM 的 JSON 静默乱码 | 改走 `decodeText()` |
| ✅ | `importBookFromPath` 不校验空内容 → 空书点开永久停在 Splash | 空正文直接返回错误 |
| ✅ | `readJson` 吞异常返回 fallback，随后可能用 `[]` 覆盖真数据 | 备份 + 指纹机制兜住；写盘结果改为向上返回，UI 可感知失败 |
