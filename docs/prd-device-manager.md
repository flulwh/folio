# 桌面端「管理我的手机」增量 PRD

> 3.1（增量）｜待评审｜基线：桌面端 2.6.0 + Android 3.0.0
> 沿用 Electron + React，在 `src/components/SettingsPage.jsx` 加一个导航项，不动渲染层架构

## 1. 功能定位

**在电脑上看见手机书架的全貌，不用拿起手机就能往里加书、把不要的书清掉。**

痛点来自现状：想给手机加本书只能拿起手机翻文件；想确认"手机还缺哪几本"只能一个个对；手机还剩多少空间，电脑这边完全不知道。

不做"多设备管理中心"——单人自用、一部手机，这页只回答三件事：**它连过吗 / 它有什么 / 我能让它做什么**。

## 2. 设备识别与记录

**标识从哪来**：手机首次运行生成 `installId`（UUID v4）存 SharedPreferences，永不变更、卸载重装即换新；每个请求带 `X-Folio-Device: <installId>` 与 `X-Folio-Device-Name: <Build.MODEL 可读名>`。桌面端在鉴权的同时记录设备活动，设备没来过就自动建记录。**不用 IP / MAC 做身份**（DHCP 会变，Android 10+ 拿不到 MAC）。

**设备对象**（存 `dataDir/devices.json`）：

| 字段 | 说明 |
| --- | --- |
| `id` / `name` | `installId` 主键；手机名，可在桌面端改名 |
| `platform` / `appVersion` / `apiVersion` | 版本过旧时禁用不可用指令 |
| `firstSeenAt` / `lastSeenAt` / `lastIp` | IP 只作排障展示，不作身份 |
| `online` | 派生：存在打开的 SSE 连接，或 90s 内有认证请求 |
| `snapshot` | 手机上报的书架快照 `[{hash,title,size,hasLocalFile}]` + 存储占用 + `snapshotAt` |
| `commands` / `history` | 指令队列；最近 50 条执行记录 |

只保留最近 5 条设备记录，超出按 `lastSeenAt` 淘汰。

**数据来源**：手机在连接成功 / 同步结束 / 退出阅读器时 `POST` 一次书架快照与存储占用（低频，不轮询）；连接成功后 `GET` 一次待执行指令，逐条 `POST` 回执。桌面端用已有 SSE 把 `device` / `command` 事件推给渲染层。

## 3. 能看到什么

**在线（SSE 连着）**：手机名 + 绿点 + IP + App 版本 + 连接时长；书架列表（书名/作者/大小/进度 + 差异标记"桌面端没有这本书""两端内容不一致"）；存储（总容量/可用/书籍占用/快照时间）；动作全部可用。

**离线（上次在线 3 天前）**：灰点 + "上次在线 3 天前（10-02 21:14）"，**不出现"在线中""正在同步"**；书架与存储整块置灰并加"3 天前的快照，可能已过期"角标；动作可入队但不承诺立即生效，实时只读动作标"需要手机在线"。

**从未连过**：空态 + "打开手机上的 Folio，在设置里连接这台电脑"。

## 4. 能操作什么

| 动作 | 入口 | 手机不在线 | 危险度 |
| --- | --- | --- | --- |
| A1 推一本书到手机 | 设备页"发送到手机"；桌面端书架右键也加一项 | 入队，标"待手机连接时执行" | 低 |
| A2 从手机书架移走一本书 | 设备页书条目的"移除" | 入队 | **高，二次确认** |
| A3 一次性补齐（桌面端所有本地书推给手机） | 设备页主按钮，自动算差集 | 入队，单批 ≤50 本 / ≤2GB | 中，确认清单与总量 |
| A4 查看手机存储占用 | 设备页存储卡 | 显示上次快照 + 时间 | 无 |
| A5 管理待执行队列 | "待执行 N 项"折叠区 | — | 无 |
| A6 从手机复制一本书到电脑 | 设备页书条目"拉到电脑" | 入队 | 低 |

**指令模型（离线场景的核心）**：指令 = `{id, deviceId, type, payload, createdAt, expiresAt, state}`，状态 `pending → delivered → done / failed`，或 `expired`。

- **寿命 7 天**：到期转 `expired`，不执行、不静默重发，留一条记录可一键重发。理由：手机可能一周不连，指令不能堆成"一连接就删掉一堆书"。
- **去重**：同一 `type + hash` 只留最新 pending，重复点击只刷时间。
- **失败回执**：空间不足 / 超 30MiB / hash 校验失败 / 网络中断 / 用户拒绝，桌面端红点 + 写明原因，可单条重试。
- **A2 特殊规则**：若桌面端没有同 hash 副本（手机独有），不允许直接执行——手机下次打开时弹确认，拒绝则回执"用户拒绝"。

**确认文案**：A2 `把《xxx》从手机上删掉？电脑上的副本不受影响。`（独有副本加红字：`手机上是唯一副本，手机端会再问你一次。`）；A3 列出 N 本与总大小，勾选"我知道会占用约 XX MB"后才可执行。

## 5. 两种状态下的界面行为

| | 在线 | 离线 |
| --- | --- | --- |
| 状态条 | 绿点 · "手机在线 · 1 分钟前同步过" | 灰点 · "手机离线 · 上次在线 3 天前" |
| 书架 | 实时，可直接操作 | 快照，置灰 + 时间角标，禁用"实时"字样 |
| 动作 | 立即下发 | 文案改"待执行"，注明"手机连接后自动执行，7 天内有效" |
| 队列 | 执行中 / 已完成 / 失败 | 待执行 N 项 · 最早一条 3 天前 |
| 禁止词 | — | 不允许"正在同步""已同步到手机"，只能说"等待手机连接" |

实现上只靠 `online` 一个布尔量切换两套呈现，不做第二套组件。

## 6. 约束与不做的事

**不做**：远程控制手机阅读界面（电脑上翻手机的书、改手机排版）；账号 / 云端中转 / FCM·APNs 推送（**没有推送就没有离线实时性，这是前提不是缺陷**）；手机后台常驻或唤醒（指令只在打开 App 并连上时执行）；多用户与权限；跨网络（只同一局域网）；从电脑删手机上的云端书（云端书本来不落手机）；队列暂停 / 限速 / 定时传输（P2）。

**现实约束**：指令 7 天寿命、过期即作废、永不静默重发；单批推送 ≤50 本 / ≤2GB，超出分批；设备记录上限 5 条，重装产生新 `installId` 时旧记录标"已失联"可手动删；`devices.json` 不含访问码与手机本地路径。

## 7. 验收标准

1. Given 手机连过一次；When 关掉手机 App 再打开桌面端设备页；Then 显示"上次在线 HH:mm"，书架为快照带时间角标，无"正在同步"字样。
2. Given 手机离线；When 在桌面端推一本书；Then 生成待执行指令且可见，`expiresAt = 现在 + 7 天`。
3. Given 一条 7 天前的待执行指令；When 手机首次连接；Then 该指令不执行、转"已过期"，不批量删除任何书。
4. Given 手机在线且空间足够；When 推一本 8MiB 的 txt；Then 手机书架出现该书，桌面端记录"已完成 + 时间 + 大小"。
5. Given 手机可用空间小于文件；When 执行 A1；Then 回执"空间不足"，记录写明原因且不重试，手机不留半个文件。
6. Given 手机上有桌面端没有的独有书；When 桌面端点"移除"；Then 手机端弹确认，拒绝时桌面端显示"用户拒绝"。
7. Given 两端书架有差异；When 打开设备页；Then 每条能看出"桌面端没有 / 内容不一致"，可用 A3 一次补齐差集。
8. Given 手机重装 App；When 再次连接；Then 出现新设备记录，旧记录标"已失联"可手动删，历史不串。

## 8. 待确认问题

1. **是否允许删掉手机上的"唯一副本"？** 当前：允许发起，手机端必须二次确认。若希望彻底禁止，A2 只对"桌面端也有同 hash"的书开放。
2. **指令寿命 7 天是否合适？** 也可"永久保留直到手动取消"（风险是一连接就连续删书），或折中：删除类 7 天、补书类永久。
3. **手机重装算不算同一台设备？** 当前按 `installId` 视为新设备。若要沿用旧记录，需按"手机名 + 型号"模糊匹配合并，成本更高但设备页不会出现两条。
